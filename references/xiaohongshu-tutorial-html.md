# 小红书教程 HTML 渲染路线

## 适用范围

`xiaohongshu-tutorial` 用于步骤、方法、工具拆解、框架说明、教程和信息密集型图文。默认制作 HTML 或 React 页面，再通过浏览器导出 PNG。该路线不负责小红书登录、发布、定时发布、数据采集或数据运营。

## 页面内容合同

每页先回答一个读者问题，再组织页面内容。默认页面合同如下：

1. 页面标题：一句能独立理解的结论或问题。
2. 解释句：说明这一页对读者有什么帮助。
3. 输入：读者需要准备的资料、对象或前置条件。
4. 动作：读者要执行的步骤、判断或交接。
5. 输出：完成后得到的文档、判断、结构或下一步。
6. 边界：适用场景、限制、风险或事实保护要求。

每页至少出现三个具体文章术语、一个动作关系和一个结果或判断。术语、数字、文件名和流程名称必须来自原文、用户提供的资料或已经核验的上下文，禁止添加来源不明的命令、参数、案例结果和承诺。

## 作者视角

来源属于用户本人或原作者的经历、教程、测评和复盘时，发布文案和页面可见文字默认采用作者第一人称。直接写操作过程、观察结果和判断依据，避免从旁观者角度介绍来源内容。

推荐表达：

```text
我先上传原始数据，再说明时间范围和比较维度。
测试时我发现，交付里少了提示词，于是补了一次修订。
我会把重复执行交给工具，同时亲自把关事实和最后取舍。
```

需要避免的表达：

```text
文章里说到
原文提到
作者发现
文中展示了
```

第一人称只能覆盖来源中明确发生的事实。第三方新闻、研究、引用和他人案例保留归因。把视角写入 `requirements.json`，值使用 `author-first-person` 或 `attributed-source`。

## 截图素材整合

资料含截图、照片、图表或界面图片时，先建立 `asset_manifest.json`：

```json
{
  "asset_id": "asset-01",
  "source_order": 1,
  "source_location": "章节或段落",
  "adjacent_explanation": "与图片直接对应的说明",
  "original_size": "1920x1080",
  "content_role": "入口、步骤、结果、对比或边界",
  "target_page": "03-step",
  "fit_policy": "contain、focus-crop、overview-detail"
}
```

页面排版遵循以下规则：

1. 截图和对应解释优先放在同一张 3:4 卡片中，形成“截图证据加作者说明”的完整阅读单元。
2. 单张关键截图使用大图加底部解释；两张截图表达输入与结果时使用上下或左右对照；连续步骤使用编号截图组；长截图使用总览加局部放大。
3. 优先使用 `object-fit: contain` 保持原始比例。只有无关空白明显挤占阅读空间时才使用焦点裁切，并确保关键界面、上下文和结果仍然完整。
4. 截图中的文字过小时，拆页、放大重点或增加局部卡片。不要把整张长截图压缩到手机端无法辨认。
5. 框选、箭头、编号和解释文字放在 HTML 或 SVG 标注层中，不能写入或重绘原始截图，也不能遮挡关键数据和控件。
6. 每张截图必须与相邻说明一一对应。禁止错配素材、重复使用无关截图或用装饰图替代事实证据。
7. 记录已提取素材数、实际使用素材数和未使用原因，便于后续扩展页面和复核。

## 推荐页面结构

教程型小红书建议八至十二页，常用推进顺序如下：

1. 封面钩子
2. 问题确认
3. 判断方法
4. 核心工具或方法一
5. 核心工具或方法二
6. 核心工具或方法三
7. 类型分流或对比
8. 风险、边界或质量检查
9. 组合路线
10. 行动清单

内容多时，为每个核心工具单独分配页面。不要把六个工具压缩到一张总览图中，也不要为了凑页数复制相同的卡片。

## 视觉实现

默认页面为 `1080x1440`，输出 PNG 宽高比为 `3:4`。HTML 页面应使用固定画布、清晰的安全边距和稳定的中文字体栈，例如 `"Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。颜色、纸张、网格、便签和流程线可以用 CSS 与内嵌 SVG 表达，避免依赖远程字体、远程图片和网络接口。

页面需要有明显的标题层级、信息分区、流程方向和视觉锚点。装饰元素不能覆盖正文，也不能占用主要信息区域。字数过多时优先拆页，保持正文卡片有足够行高和留白，不通过极小字号解决溢出。

## 渲染与验证

1. 保存每页 HTML 源文件，保留可追溯的页面编号和输出文件名。
2. 用真实浏览器以 `1080x1440` 视口加载本地 HTML。
3. 导出 PNG 到 `images/`，文件名与页面计划和需求契约一致。
4. 检查控制台、资源加载、页面溢出和元素重叠。
5. 检查 PNG 的像素尺寸、准确比例、文字清晰度、裁切和缩略图可读性。
6. 记录 HTML 检查和 PNG 检查的独立结果。
7. 使用作者第一人称时，运行 `python -X utf8 scripts/check_xiaohongshu_copy.py <output-dir>`。
8. 使用来源截图时，检查截图清晰度、原始比例、关键内容裁切、素材与说明对应关系，以及截图事实内容是否保持原样。

# 小红书教程 HTML 渲染路线

## 适用范围

`xiaohongshu-tutorial` 用于步骤、方法、工具拆解、框架说明、教程和信息密集型图文。默认制作 HTML 或 React 页面，再通过浏览器导出 PNG。该路线不负责小红书登录、发布、定时发布、数据采集或数据运营。

## 页面内容合同

每页先回答一个读者问题，再组织页面内容。默认页面合同如下：

1. 页面标题：一句能独立理解的结论或问题。
2. 解释句：说明这一页对读者有什么帮助。
3. 输入：读者需要准备的资料、对象或前置条件。
4. 动作：读者要执行的步骤、判断或交接。
5. 输出：完成后得到的文档、判断、结构或下一步。
6. 边界：适用场景、限制、风险或事实保护要求。

每页至少出现三个具体文章术语、一个动作关系和一个结果或判断。术语、数字、文件名和流程名称必须来自原文、用户提供的资料或已经核验的上下文，禁止添加来源不明的命令、参数、案例结果和承诺。

## 作者视角

来源属于用户本人或原作者的经历、教程、测评和复盘时，发布文案和页面可见文字默认采用作者第一人称。直接写操作过程、观察结果和判断依据，避免从旁观者角度介绍来源内容。

推荐表达：

```text
我先上传原始数据，再说明时间范围和比较维度。
测试时我发现，交付里少了提示词，于是补了一次修订。
我会把重复执行交给工具，同时亲自把关事实和最后取舍。
```

需要避免的表达：

```text
文章里说到
原文提到
作者发现
文中展示了
```

第一人称只能覆盖来源中明确发生的事实。第三方新闻、研究、引用和他人案例保留归因。把视角写入 `requirements.json`，值使用 `author-first-person` 或 `attributed-source`。

## 截图素材整合

资料含截图、照片、图表或界面图片时，先建立 `asset_manifest.json`：

```json
{
  "asset_id": "asset-01",
  "source_order": 1,
  "source_location": "章节或段落",
  "adjacent_explanation": "与图片直接对应的说明",
  "original_size": "1920x1080",
  "content_role": "入口、步骤、结果、对比或边界",
  "target_page": "03-step",
  "fit_policy": "contain、focus-crop、overview-detail"
}
```

页面排版遵循以下规则：

1. 截图和对应解释优先放在同一张 3:4 卡片中，形成“截图证据加作者说明”的完整阅读单元。
2. 单张关键截图使用大图加底部解释；两张截图表达输入与结果时使用上下或左右对照；连续步骤使用编号截图组；长截图使用总览加局部放大。
3. 优先使用 `object-fit: contain` 保持原始比例。只有无关空白明显挤占阅读空间时才使用焦点裁切，并确保关键界面、上下文和结果仍然完整。
4. 截图中的文字过小时，拆页、放大重点或增加局部卡片。不要把整张长截图压缩到手机端无法辨认。
5. 框选、箭头、编号和解释文字放在 HTML 或 SVG 标注层中，不能写入或重绘原始截图，也不能遮挡关键数据和控件。
6. 每张截图必须与相邻说明一一对应。禁止错配素材、重复使用无关截图或用装饰图替代事实证据。
7. 记录已提取素材数、实际使用素材数和未使用原因，便于后续扩展页面和复核。

## 推荐页面结构

教程型小红书建议八至十二页，常用推进顺序如下：

1. 封面钩子
2. 问题确认
3. 判断方法
4. 核心工具或方法一
5. 核心工具或方法二
6. 核心工具或方法三
7. 类型分流或对比
8. 风险、边界或质量检查
9. 组合路线
10. 行动清单

内容多时，为每个核心工具单独分配页面。不要把六个工具压缩到一张总览图中，也不要为了凑页数复制相同的卡片。

## 视觉实现

默认页面为 `1080x1440`，输出 PNG 宽高比为 `3:4`。HTML 页面应使用固定画布、清晰的安全边距和稳定的中文字体栈，例如 `"Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。颜色、纸张、网格、便签和流程线可以用 CSS 与内嵌 SVG 表达，避免依赖远程字体、远程图片和网络接口。

页面需要有明显的标题层级、信息分区、流程方向和视觉锚点。装饰元素不能覆盖正文，也不能占用主要信息区域。字数过多时优先拆页，保持正文卡片有足够行高和留白，不通过极小字号解决溢出。

## 渲染与验证

1. 保存每页 HTML 源文件，保留可追溯的页面编号和输出文件名。
2. 使用 `python -X utf8 scripts/build_xiaohongshu_preview.py <output-dir>` 生成根目录的 `index.html`，集中审阅发布文案、页面顺序、单页 HTML 和素材映射。
3. 用真实浏览器以 `1080x1440` 视口加载每个单页 HTML。
4. 导出 PNG 到 `images/`，文件名与页面计划和需求契约一致。
5. 再次生成整体页，并使用 `--require-images` 校验所有页面都已有最终 PNG。
6. 检查控制台、资源加载、页面溢出和元素重叠。
7. 检查 PNG 的像素尺寸、准确比例、文字清晰度、裁切和缩略图可读性。
8. 记录 HTML 检查、PNG 检查和整体交付页检查的独立结果。
9. 使用作者第一人称时，运行 `python -X utf8 scripts/check_xiaohongshu_copy.py <output-dir>`。
10. 使用来源截图时，检查截图清晰度、原始比例、关键内容裁切、素材与说明对应关系，以及截图事实内容是否保持原样。

## 整体交付预览页

`index.html` 是小红书图文包的审阅和交付入口，使用相对路径引用包内文件，避免远程字体、远程脚本和网络接口。它至少展示：

1. 发布标题、正文、标签和互动引导，并提供复制按钮。
2. 全部页面的发布顺序、页面职责、来源素材和版式说明。
3. 导出前的单页 HTML 预览，或导出后的最终 PNG。
4. HTML 打开入口和单张 PNG 下载入口。
5. 来源素材数量、目标页面和解释关系。
6. `qa.md` 中的检查记录，以及 HTML、PNG 和页面数量状态。

整体页负责集中查看和交接，独立的 `html/NN-*.html` 继续作为最终成图源。修改单页后只重新渲染对应 PNG，再刷新 `index.html`。禁止从一个超长整体页面按位置切割图片，因为这种方式会隐藏单页溢出、裁切和字体问题。

### 预览主题自适应

预览页是当前图文包的编辑控制台，视觉主题必须来自当前产物，不使用与文章无关的通用图库外观。实现前读取 `requirements.json`、`brief.md`、`plan.md` 和 `qa.md`，同时检查实际封面、机制或步骤页、风险或边界页。至少提取以下信号：

1. 成图主色、背景明暗和强调色关系
2. 标题字体行为、正文密度、数字和代码的排版方式
3. 卡片边框、圆角、网格、终端、节点、纸张或其他材质语言
4. 文章类型、核心主张、页面职责、风险边界和素材可用性

将这些信号编译成预览页的本地主题 token、首屏构图、导航标签、状态色、图片卡片层级和详情区文案。例：系统型工具教程可以使用与成图相同的深色底、青蓝高亮、薄荷绿通过状态、终端或插件节点语义；人物经验或生活方式内容应依据实际成图切换为对应的叙事材质。不得把一套固定深色或固定浅色模板套用到所有文章。

预览页最少要让审阅者在首屏看见文章核心主张、当前封面和交付状态，在图片序列中看见页面职责与内容推进，在素材和质量区看见来源状态、边界说明和真实检查结果。主题变化不能牺牲复制文案、图片放大、HTML 打开、PNG 下载和折叠详情等功能。

预览页完成后，用真实浏览器至少检查桌面宽度和 390px 左右的窄屏宽度。确认 `body.scrollWidth` 不超过视口宽度，所有最终图片加载成功，标题和标签没有竖排或截断，图片放大弹窗可关闭，复制按钮有反馈，详情区可展开。资源全部使用相对本地路径，并为页面提供本地 favicon 或数据 URI，避免把无关的资源 404 当成页面质量通过。

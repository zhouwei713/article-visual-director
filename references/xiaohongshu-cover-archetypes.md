# 小红书封面结构

封面结构是内容到视觉的组织方式，不是固定模板。每次使用时都要根据文章主张重新选择主体、尺度、颜色和文字层级。

## 结果冲突

适合工具测评、效率提升、经验总结和前后变化。

```text
核心关系：结果信号 + 造成变化的关键动作
视觉锚点：一个明显的前后差异或结果物
标题策略：短主标题，必要时加入真实数字
风险：不能用未经文章支持的夸张结果
```

## 数字证据

适合数据、成本、时间、版本差异和实验记录。

```text
核心关系：一个真实数字 + 它改变了什么判断
视觉锚点：数字、仪表、清晰表格或可观察结果
标题策略：数字必须来自原文或用户资料
风险：不能把装饰性数字当作事实
```

## 界面证据

适合软件教程、AI 工具和操作经验。

```text
核心关系：界面入口 + 用户动作 + 输出结果
视觉锚点：真实界面区域或操作前后变化
标题策略：说明工具和具体用途
风险：避免虚构按钮、品牌界面和不存在的功能
```

## 人物与行动

适合个人经验、职业故事、学习记录和生活方式内容。

```text
核心关系：成年原创人物 + 一个具体动作 + 一个可观察物件
视觉锚点：人物动作或与文章相关的物件
标题策略：强调处境、转折或经验结论
风险：完整遮盖、非露骨，不使用可识别真实人物
```

## 前后对照

适合改造、整理、流程优化、错误修正和方法升级。

```text
核心关系：旧状态与新状态的明确差异
视觉锚点：左右或上下对比中的决定性变化
标题策略：前后关系清楚，避免只写“之前”和“之后”
风险：两侧必须来自真实文章内容，不能凭空制造结果
```

## 概念张力

适合观点、行业判断、抽象机制和文章主张。

```text
核心关系：一个可解释的隐喻 + 一个明确冲突
视觉锚点：尺度反差、空间阻隔、方向相反的动作或异常关系
标题策略：主标题成为第一视觉层级
风险：隐喻必须能回扣文章，避免普通科技背景
```

## 冲击机制

封面结构负责表达什么内容，冲击机制负责第一眼如何抓住注意力。每张封面只选择一种主要冲击机制，并在 `requirements.json`、`plan.md` 和 AI 封面提示词元数据中记录 `impact_mechanism`。

### 巨字透视 `giant-type-perspective`

让四至八个汉字的视觉短标题成为空间主体，通过透视、尺度、阴影、斜切或建筑体量制造速度和压迫感。透视不能破坏字形识别。

### 图文咬合 `type-subject-interlock`

让标题与人物、产品或物件形成经过设计的前后遮挡。至少存在一次清楚的主体遮字或文字压主体关系，同时保证标题完整可读。

### 近景推进 `foreground-thrust`

让一个产品、道具、结果卡或关键物件向镜头推进，利用近大远小、轻微运动感和人物动作建立现场张力。前景物不能遮住核心标题和事实证据。

### 动作瞬间 `decisive-action`

截取动作即将发生、正在发生或刚刚完成的瞬间。必须写清人物或主体的位置、视线、手部动作、道具轨迹和结果信号，避免只依赖夸张表情。

### 尺度冲突 `scale-tension`

用巨大与微小、远与近、完整与破裂、阻隔与穿透等单一关系表达文章冲突。画面只保留一个主视觉中心。

### 单一隐喻 `single-metaphor`

把文章最重要的关系、动作或变化转译成一个可解释的实体隐喻。每个元素都要承担语义，排除无关装饰和通用科技符号。

## AI 封面契约

使用 `imagegen` 时额外记录：

```text
render_method
impact_mechanism
hero_subject
decisive_action
depth_relation
title_subject_interlock
click_hook
visual_anchor
safe_crop_zone
thumbnail_readability
```

人物、标题和主要道具距四边保留约百分之十的安全空间。真人并非默认元素，只有人物身份、动作或账号识别度能强化主题时才使用。中文主标题需要逐字检查，出现错字、缺字、异常变形、严重遮挡或缩略图不可读时判定失败并重新生成该项。

## 封面检查

生成前确认：

1. 3:4 比例和安全裁切区已经写入契约
2. 只有一个主要视觉锚点
3. 点击钩子来自文章内容
4. 主标题在缩略图中仍然可读
5. 数字、产品、人物和结果没有未经来源支持的内容
6. 画面没有网格拼版、候选联系表或大段小字
7. 已记录一种明确的冲击机制，且能在缩略图中看见
8. AI 封面已检查标题与主体的空间关系、人物动作和前中后景

# 科技文章编辑型封面

用于技术文章、开源项目、AI 工具和基础设施主题的高概念文章封面，尤其适用于用户提供了视觉参考图的任务。

## 适用判断

满足以下任意两项时，采用 `cinematic-editorial-tech` 视觉模式和 `editorial-system-landscape` 结构：

1. 文章标题包含项目名、技术名或开源发布信息
2. 用户希望封面同时说明文章主题和核心观点
3. 参考图具有左侧标题区、右侧叙事场景或底部关键词层
4. 文章包含三个以上可视化模块、能力或系统部件
5. 用户反馈单一口号海报信息不足、画面太空或缺少文章识别度

## 文字层级

保持一个一级主标题，允许存在少量二级和三级文字。主标题仍然是第一视觉焦点，丰富信息用于建立文章身份和可信度。

### 公众号

推荐使用：

1. 文章项目标题
2. 一句短副标题
3. 核心概念词
4. 三至五个真实模块标签
5. 一句不超过二十字的解释性文案

完整正文不放入封面。小字必须控制数量、长度和对比度，缩略图中不依赖小字才能读懂主题。

### X Article

推荐使用：

1. 核心主标题
2. 一句短副标题
3. 不超过三个核心关键词

X 封面优先保留大标题和场景轮廓，删减公众号版的解释性文案与功能标签。

## 视觉结构

编辑型科技封面可以使用以下空间关系，但每次根据文章重新设计：

1. 左侧或上方建立标题阅读区
2. 右侧或后方建立文章核心隐喻场景
3. 中央或右侧设置唯一强视觉动作，例如插入、打开、穿越、连接、拆分或重新组合
4. 使用前景、中景和后景建立尺度与空间深度
5. 使用一条光线、一道入口、一个缺口或一个动作把文字和场景连成同一语义

禁止把它制作成流程图、功能列表或产品广告页。标签必须服务于文章身份，场景必须服务于文章主张。

## DeepSeek Harness 类文章的视觉推导示例

当文章讨论模型、工具、沙箱、会话、权限和运行轨迹可以作为可替换、可组合的插件时，可以使用：

1. 深色模块化结构或拼接墙体，表达可替换部件
2. 一个明亮入口或打开的缺口，表达能力被重新激活
3. 一个远景成年人物，表达从运行底盘进入可扩展系统
4. 蓝色线性标签，表达模块身份和系统可观察性
5. 低饱和深蓝与冷白光的对比，表达基础设施、秩序和能力释放

这些元素只是一组语义候选。若文章核心观点变化，必须重新推导主体、光线、尺度和颜色。

## 参考图提取规则

参考图使用 `style` 或 `style-and-structure` 语义时，提取：

1. 标题的层级和相对位置
2. 画面左右的重量关系
3. 主色、强调色和光线方向
4. 主体尺度和前中后景关系
5. 信息密度和标签数量
6. 质感、颗粒、雾气和边缘处理

不要复制参考图的具体文案、Logo、人物身份或独特物体组合。用户要求直接编辑参考图时，才使用 `direct` 引用。

## 失败模式

以下情况判定为编辑型封面失败：

1. 只剩一句口号和一个装饰物，无法识别文章主题
2. 文章标题、项目名或核心模块全部消失
3. 场景只有科技背景，没有可解释的动作或空间关系
4. 小标签数量过多，画面变成信息长图
5. 深色科技主题被错误转译成廉价霓虹或通用服务器渲染
6. 参考图的版式层级、视觉重心和叙事动作完全丢失
